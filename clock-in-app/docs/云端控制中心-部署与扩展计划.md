## 1. 现状：已经完成的部分

系统已经可以运行，包括服务器、员工打卡端、管理后台，并经过自动化测试。**云端控制中心本身已经写好了**，还缺的是**把它部署到一台云服务器上**，以及一些可选的增强功能。

### 1.1 架构

```
员工打卡电脑（浏览器）──┐
                        ├──HTTPS──▶ 云服务器: Caddy(443) ──▶ Node.js server.js(127.0.0.1:8080) ──▶ data/db.json
老板手机/电脑（浏览器）──┘
```

- **server/server.js**：Node.js 18+ 原生 `http` 模块，无第三方依赖。提供静态网页 + JSON API
- **server/public/rules.js**：工资与考勤规则引擎，**服务器和浏览器共用同一份**（UMD 模块）
- **server/public/index.html**：员工打卡端（只能打卡、看自己的考勤）
- **server/public/admin.html**：管理后台（路径 `/admin`）
- **server/public/ui.js、theme.css**：两个页面共用的界面工具和样式
- **存储**：`DATA_DIR/db.json`（原子写入：先写 .tmp 再 rename），每天自动备份到 `DATA_DIR/backups/db-YYYY-MM-DD.json`，保留 90 天
- **时区**：所有日期按 `settings.tzOffset`（默认 +8）计算，与服务器所在时区无关

### 1.2 环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `PORT` | 8080 | 监听端口 |
| `HOST` | 0.0.0.0 | 监听地址。放在反向代理后面时设为 `127.0.0.1` |
| `DATA_DIR` | `./data` | 数据目录 |
| `TRUST_PROXY` | 空 | 设为 `1` 时信任 `X-Forwarded-For` / `X-Forwarded-Proto`（用于获取真实 IP、给 Cookie 加 Secure） |

### 1.3 鉴权

- **管理员**：首次启动时服务器在控制台打印 6 位**初始化码**，在 `/admin` 用初始化码设置密码（scrypt 加盐哈希）。登录后发 `sp_admin` Cookie（HttpOnly、SameSite=Strict，12 小时滑动过期，会话存内存，重启需重新登录）。POST 请求必须带请求头 `X-Requested-With: starpunch`（防 CSRF）
- **打卡终端**：请求头 `X-Terminal-Key` 必须等于终端激活码（形如 `ABCD-1234`，可在后台更换）
- **员工打卡密码**：可选，scrypt 哈希存储
- **限流**：登录 / 初始化 / 终端码 / 打卡密码，同一来源连续失败 8 次锁 10 分钟

### 1.4 数据模型（db.json）

```js
{
  version: 2,
  settings: { company, salary, commissionRate /*默认提成%*/, payDay /*1-28*/, inDL: "11:00", taskDL: "16:00",
              undoneRatio /*0|0.5|1*/, tzOffset: 8, installedAt: "YYYY-MM-DD" },
  secrets:  { adminSalt, adminHash, terminalKey, setupCode },          // 永不发给浏览器
  employees: [{ id, name, avatar, salary, commissionRate /*null=用默认*/, hireDate, active, leftAt, createdAt, pinSalt?, pinHash? }],
  records:  { "员工id|YYYY-MM-DD": { in: 时间戳ms, done: 时间戳ms, note, edited, editLog: [{at, from, to, why}] } },
  perf:     [{ id, empId, date, amount, note, createdAt }],           // 业绩
  payrolls: [{ id, empId, empName, avatar, period: "YYYY-MM", payDate, salary, days, eligible, rate, counts,
               base, perfTotal, commissionRate, commission, amount, createdAt, paid, paidAt }],
  badges:   { 员工id: { 成就key: 解锁时间戳 } },
  audit:    [{ at, ip, action, detail }]                               // 最多保留 5000 条
}
```

### 1.5 API

员工端（需 `X-Terminal-Key`）：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/client/state` | 服务器时间、公开设置、在职员工今日状态 / 本月汇总 / 连胜 / 成就 |
| GET | `/api/client/month?emp=&ym=YYYY-MM` | 某员工某月每日考勤 + 汇总 |
| POST | `/api/client/punch` | `{empId, type: "in"\|"done", pin?, note?}`，时间取服务器时间 |

管理后台（需登录 Cookie）：`GET /api/admin/status`、`POST /api/admin/setup`、`POST /api/admin/login`、`POST /api/admin/logout`、`GET /api/admin/state`、`GET /api/admin/backup`，以及 POST：`employee`、`employee/toggle`、`employee/delete`、`record`（补卡，必须填原因）、`perf`、`perf/delete`、`payroll/mark`、`payroll/recalc`、`settings`、`password`、`terminal-key/reset`、`restore`。所有修改都会写入 `audit`。

### 1.6 业务规则（不要改）

- 没有休息日，每天都要打卡；日薪 = 月薪 ÷ 当月天数
- 上班截止前打卡 且 任务截止前完成 → 100%；截止后上班、任务截止前完成 → 50%；截止后上班且任务截止前未完成 → 0；准时但未按时完成 → `undoneRatio`；没打上班卡 → 缺勤 0
- 提成 = 当月业绩合计 × 提成比例（员工单独设置优先，否则用默认）
- 每月 `payDay` 日 0 点之后，自动生成**上一个自然月**的结算快照；未发放的结算在补卡 / 改业绩后自动重算，已发放的锁定不变

## 2. 任务一（必做）：部署到云服务器

### 2.1 需要老板先决定 / 准备的

1. **买一台云服务器**：阿里云 / 腾讯云的「轻量应用服务器」即可，**2 核 2G**、系统选 **Ubuntu 22.04**，几十元一个月
   - **选中国香港地域**：不需要备案，买完当天就能用（推荐）
   - **选内地地域**：如果要用域名访问，需要先做 **ICP 备案**（一般需要 1–3 周）
2. **（强烈建议）买一个域名**，例如 `daka.你的品牌.com`，解析一条 A 记录到服务器公网 IP。有域名才能用 HTTPS（加密传输，否则管理员密码会以明文在网络上传输）
3. 在云服务器控制台的**防火墙 / 安全组**里放行端口 **22、80、443**

### 2.2 部署步骤（ChatGPT 请按此执行并给出逐条命令）

1. SSH 登录服务器（可以用云厂商网页上的「远程登录」按钮）
2. 安装 Node.js 20 LTS：`curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash - && sudo apt-get install -y nodejs`，用 `node -v` 确认版本 ≥ 18
3. 创建专用用户和目录：`sudo useradd -r -s /usr/sbin/nologin starpunch`，代码放到 `/opt/starpunch/server`，数据目录 `/var/lib/starpunch`（属主改为 starpunch）
4. 上传 `server` 文件夹（可用云厂商网页的文件上传、`scp` 或 `git clone`）
5. 创建 systemd 服务 `/etc/systemd/system/starpunch.service`：
   ```ini
   [Unit]
   Description=StarPunch clock-in server
   After=network.target

   [Service]
   User=starpunch
   WorkingDirectory=/opt/starpunch/server
   Environment=PORT=8080 HOST=127.0.0.1 DATA_DIR=/var/lib/starpunch TRUST_PROXY=1
   ExecStart=/usr/bin/node server.js
   Restart=always
   RestartSec=3

   [Install]
   WantedBy=multi-user.target
   ```
   然后执行 `sudo systemctl daemon-reload && sudo systemctl enable --now starpunch`
6. 查看初始化码和终端激活码：`sudo journalctl -u starpunch -n 30 --no-pager`
7. 安装 Caddy（按官方文档 <https://caddyserver.com/docs/install#debian-ubuntu-raspbian>），`/etc/caddy/Caddyfile` 写：
   ```
   daka.example.com {
       encode gzip
       reverse_proxy 127.0.0.1:8080
   }
   ```
   `sudo systemctl reload caddy`。Caddy 会自动申请 HTTPS 证书
8. 浏览器打开 `https://daka.example.com/admin`，用初始化码设置管理员密码
9. 员工电脑：把 `员工打卡端.bat` 里的 `SERVER` 改成 `https://daka.example.com`，双击打开，输入终端激活码
10. **没有域名时的临时方案**（仅测试用）：跳过第 7 步，把 `HOST` 改为 `0.0.0.0`、去掉 `TRUST_PROXY`，安全组放行 8080，用 `http://服务器IP:8080` 访问。正式使用前务必换成域名 + HTTPS

### 2.3 异地备份（建议）

服务器已经每天在 `/var/lib/starpunch/backups` 自动备份。再加一层异地备份：用 cron 每天把该目录同步到阿里云 OSS / 腾讯云 COS（`ossutil` / `coscmd`），或者老板每月在后台「设置 → 下载完整备份」手动保存一份。

### 2.4 以后怎么更新程序

替换 `/opt/starpunch/server` 里的代码文件（**不要动** `/var/lib/starpunch` 数据目录），然后 `sudo systemctl restart starpunch`。重启后管理员需要重新登录，员工端会自动重连。

### 2.5 验收清单

- [ ] `https://域名/admin` 能打开，浏览器地址栏显示小锁（HTTPS）
- [ ] 能用初始化码设置密码，能登录，能添加员工
- [ ] 员工电脑输入激活码后能打卡，后台「总览」30 秒内能看到这次打卡
- [ ] 用手机 4G 网络（不连店里 WiFi）也能打开管理后台
- [ ] `sudo systemctl restart starpunch` 后数据还在
- [ ] `sudo reboot` 重启服务器后服务自动恢复
- [ ] `/var/lib/starpunch/backups` 里有当天的备份文件

## 3. 可选增强（按需要挑着做）

### 3.1 企业微信 / 钉钉群通知（推荐，工作量小）

在 `settings` 里加一个 `webhookUrl`（企业微信群机器人 Webhook），在 `server.js` 的 `tick()` 里定时发送：
- 每天 11:05：今天还没打上班卡的员工名单
- 每天 16:05：今日出勤汇总（正常 / 迟到 / 未完成）
- 发薪日 9:00：本次结算明细与合计
- 在后台「设置」页加输入框和「发送测试消息」按钮

### 3.2 只允许在店里打卡

在 `settings` 里加 `allowedIps`（IP 白名单，店里宽带的公网 IP），`/api/client/punch` 校验来源 IP（`TRUST_PROXY=1` 时取 `X-Forwarded-For` 第一个）。后台加设置项和「显示我当前的 IP」按钮。

### 3.3 管理后台手机适配

目前后台按电脑屏幕设计，手机能用但考勤矩阵需要横向滑动。可以为窄屏（<700px）增加：总览卡片单列、考勤改为「选员工 → 月历」视图。

### 3.4 以后再说

- 请假 / 调休：给某员工某天标记「请假」，规则决定是否扣薪（需要在 `rules.js` 的 `evalDay` 里加一个新状态，并同步修改两个前端的图例）
- 阶梯提成：业绩分段对应不同比例（修改 `computeMonth` 里的提成计算）
- 多个管理员 / 只读账号（例如会计只能看不能改）
- 员工超过 50 人时，把 JSON 存储迁移到 SQLite

## 4. 已知限制

- 管理员会话存在内存里，服务器重启后需要重新登录（这是有意的，简单且安全）
- 单进程 + JSON 文件，适合 50 人以内的团队。不要开多个实例同时写同一个 `db.json`
- 员工端离线时无法打卡（这是有意的：打卡时间必须以服务器为准）

## 5. 开发约束（给 ChatGPT / 开发者）

1. **`server/public/rules.js` 是工资计算的唯一来源**，服务器和两个前端都调用它。不要在别处复制计算逻辑；修改规则时只改这里
2. 不要改变现有 API 的路径和字段含义；新增字段要保证旧的 `db.json` 读进来不出错（在 `server.js` 的 `normalize()` 里补默认值）
3. 所有修改数据的管理接口都要调用 `audit()` 记录日志
4. `secrets` 和员工的 `pinHash/pinSalt` 永远不能出现在任何返回给浏览器的数据里
5. 保持零依赖（只用 Node.js 内置模块），这样部署最简单
6. 改完后至少手动验证：员工打卡 → 后台看到记录 → 补卡 → 结算金额正确
